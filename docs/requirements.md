# ShareBox 项目需求

## 1. 项目定位与文档范围

ShareBox 是部署在个人服务器上的文件发布与分享工具：管理员通过管理面板维护文件，访客通过公开端浏览和下载文件。

本文整理自《文件分享方案咨询》。原讨论已明确公开端使用 Caddy；第一版功能边界根据讨论中的最小方案整理，尚未明确的交互规则采用下文默认值。技术选型、模块协作和存储方案见 [架构设计](architecture.md)。

## 2. 使用角色

| 角色 | 能力 |
| --- | --- |
| 管理员 | 登录后上传、整理、删除文件，复制公开下载链接 |
| 访客 | 无需登录，浏览公开目录和下载文件；不能上传或修改内容 |

第一版按单管理员、单服务器设计，不提供注册和多用户权限管理。

## 3. 第一版功能

### 3.1 管理端访问认证

- 管理端直接使用 Caddy Basic Auth，通过浏览器原生认证提示输入用户名和密码。
- 未通过认证不能访问任何管理页面或执行管理操作；公开下载端无需认证。
- 用户名和密码哈希由部署者在 Caddy 配置中维护，应用不管理账号和会话。
- 第一版不制作登录页、退出按钮、会话过期提示或密码管理页面；浏览器可能缓存 Basic Auth 凭据，不提供应用级退出登录。

### 3.2 文件浏览与整理

- 浏览公开根目录及其子目录，通过面包屑返回上级。
- 显示名称、类型、文件大小和最后修改时间；不要求计算目录总大小。
- 支持新建目录、文件和目录重命名、文件移动到现有目录。
- 支持删除文件、删除空目录；删除前明确提示并确认。
- 同名目标默认拒绝，不静默覆盖；不支持移动整个目录或递归删除非空目录。
- 管理员从服务器直接放入或移除的普通文件，刷新后应反映在列表中。

### 3.3 文件上传

- 向当前目录上传文件；第一版至少支持单文件上传。
- 展示上传中、成功和失败状态，处理中避免重复提交。
- 上传完成并成功发布后，文件才出现在公开端；失败或中断不能留下可下载的残缺文件。
- 对文件过大、磁盘不足、名称冲突、权限不足等情况给出明确反馈。
- 最大文件大小由部署配置决定；第一版不实现分块上传和上传断点续传。

### 3.4 公开链接

- 为已发布文件提供可复制的完整下载 URL。
- 链接与文件路径对应，包含中文、空格等字符的文件名也应可正确访问。
- 重命名或移动会改变链接，操作时提示旧链接将失效。
- 删除后，后续对原文件地址的新请求无法继续获取该文件；不承诺中断已开始的下载或撤回已下载的副本。

### 3.5 公开浏览与下载

- 使用 Caddy 提供目录列表和文件服务，无需自建公开端 React 页面。
- 访客可以进入子目录，查看名称、文件大小和修改时间，通过文件链接获取文件。
- 支持大文件传输及兼容客户端的 Range 下载续传；续传要求文件内容未改变。
- 文件不存在时显示未找到，目录无内容时显示空目录。
- 第一版沿用静态文件的浏览器行为；图片、PDF 等可能在浏览器打开，不强制所有文件弹出保存对话框。

## 4. 页面需求

| 页面 | 内容与操作 | 必要状态 |
| --- | --- | --- |
| 文件管理页 | 当前目录、面包屑、文件列表、上传、新建目录、重命名、移动、删除、复制链接 | 加载中、空目录、处理中、成功、失败、无权限、目录已不存在 |
| 公开目录页 | Caddy 目录列表、上级和子目录入口、文件链接 | 正常列表、空目录、未找到 |

第一版以桌面浏览器的基础可用界面为默认范围，不单独制作仪表盘、设置页或自定义公开端主题。

## 5. 发布规则与运行要求

- 第一版管理的正式文件均公开可访问，不提供草稿或“仅持有链接可见”的权限语义。
- 公开目录不能包含密码、数据库、配置、日志、备份和上传临时文件。
- 管理操作必须限制在指定文件根目录内，不能访问服务器其他文件或通过符号链接越界。
- 管理端和公开端使用 HTTPS；密码不得明文保存。
- 大文件上传不能把整个文件一次性载入应用内存。
- 应用重启后文件仍保留，认证配置由 Caddy 持久保存；管理应用停止时，Caddy 仍能提供已有文件下载。
- 服务器直接导入文件也必须遵守“先完整写入，再发布”的规则，不能将传输中的文件直接写入公开目录。

## 6. 验收场景

1. 未提供或提供错误凭据访问管理页、上传入口及其他管理操作时，Caddy 返回 401；无法绕过 Caddy 从公网直连应用。
2. 通过认证后创建目录、上传文件，公开端可见且下载内容与原文件一致。
3. 上传中和上传失败时，公开端无法访问该次上传的临时内容。
4. 同名上传、重命名或移动被拒绝，原文件内容不变。
5. 重命名或移动文件后，新链接可用，旧链接的新请求返回未找到；中文和空格文件名可正常下载。
6. 删除文件后，列表刷新不再显示，原链接的新请求返回未找到；非空目录删除被拒绝。
7. 服务器直接导入完整普通文件后，无需数据库登记，刷新管理端和公开端即可看到。
8. 越界路径、符号链接访问和未授权修改被拒绝；公开端无法读取临时文件、数据库或密钥。
9. 对未变更文件的有效 Range 请求返回对应字节内容；停止管理应用后，公开下载仍可用。

## 7. 后续需求与触发条件

以下内容不纳入第一版，也不预先实现对应架构。

| 后续能力 | 何时考虑 |
| --- | --- |
| 私有文件、分享 Token、密码、过期时间、次数限制 | 出现访问控制或临时分享需求时；需要重新设计下载鉴权 |
| 下载统计与审计界面 | 需要回答访问量、访问记录等问题时 |
| 多管理员、角色权限 | 多人共同管理时 |
| 分块上传、上传续传、批量操作 | 大文件上传失败或重复操作成为实际问题时 |
| 目录移动、递归删除、回收站 | 基础整理能力不足或需要恢复误删时 |
| 描述、标签、搜索、预览 | 单纯目录浏览不足以组织内容时 |
| S3 等对象存储、多服务器 | 本地容量或单机服务能力不足时 |
| 独立 API、CLI、移动客户端 | 出现 Web 管理面板之外的调用方时 |

第一版也不包含远程 URL 下载、BT/Magnet、同步客户端、WebDAV 或在线编辑。
