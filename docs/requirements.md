# ShareBox 项目需求

## 1. 项目定位

ShareBox 是个人服务器上的统一文件中转、管理与分发平台，以统一 Web 入口满足三个场景：

| 场景 | 文件流向 | 负责模块 |
| --- | --- | --- |
| 对外发布文件夹 | 服务器 → 外部用户 | Sharing：目录发布、匿名浏览与下载、取消发布 |
| 自己跨设备传递文件 | 设备 A → 服务器 → 设备 B | Transfer：认证后的上传、私有浏览与下载 |
| 服务器代下载 | 外部资源 → 服务器 | Acquisition：HTTP/HTTPS 获取、持久化任务与失败恢复 |

文件内容在文件系统中保留一份，由统一文件管理能力维护。文件默认私有，公开访问来自显式分享规则，不以两套 public/private 文件副本表达权限。产品保持单服务器、个人使用和低部署成本，不扩展为完整协作网盘或通用下载管理器。

第 2 节记录现有实现；第 3 节起是已确定方向、尚待开发和验收的目标需求，不能视为当前可用能力。

项目技术栈为 Node.js、TypeScript、React Router Framework 和 MUI。技术实现见 [架构设计](architecture.md)。

## 2. 当前版本

### 2.1 使用角色

| 角色 | 能力 |
| --- | --- |
| 管理员 | 通过认证后查看、添加和删除文件 |
| 访客 | 无需认证，浏览和下载公开文件 |

当前版本面向单服务器和单个管理员凭据，不提供注册或用户管理。

### 2.2 管理端认证

- 管理端使用应用登录页 `/login`，固定单个管理员，凭据通过环境变量配置。
- 密码使用带随机盐的 scrypt 哈希，配置中不保存明文密码。
- 签名 Cookie 会话固定有效 7 天，服务端检查签名、到期时间和凭据版本；支持 POST 退出。
- 管理页及其 loader、文件操作、全部 tus 上传方法在服务端验证会话；未登录页面跳转登录，操作和上传返回 401。
- 公开浏览及下载允许匿名访问；生产环境要求 HTTPS，Cookie 使用 HttpOnly、SameSite=Lax 和 Secure。
- 单进程共享登录限流为 15 分钟最多 10 次尝试，成功登录重置；不提供注册、会话设备管理或单独撤销会话。

### 2.3 文件管理

- 所有公开文件位于状态根目录的 `data/` 及其子目录中，以可展开、收起的目录树展示；部署只配置一个状态根目录，内部公开目录和私有上传目录由程序维护。
- 文件树显示文件名、文件大小及目录子项数量。
- 支持浏览已有子目录；当前不提供新建目录。
- 管理员可以向公开根目录添加文件。
- 管理员可以删除根目录或子目录中的文件和空目录，删除前需要确认；非空目录拒绝删除。
- 添加同名文件时拒绝操作，不覆盖已有文件。
- 文件系统是文件列表的唯一数据来源。通过服务器直接添加或删除文件后，刷新页面即可看到结果。

### 2.4 文件上传

- 使用文件选择框或拖放选择多个文件，通过 tus 协议分块传输。
- 浏览器最多保留 100 个上传任务，同时上传最多 2 个文件，默认每个文件最大 10 GiB。
- 显示每个文件的已发送字节数、百分比和状态；支持暂停、继续、失败重试和删除上传任务。
- 断线保留已落盘数据，续传以服务端偏移量为准；服务器重启后可恢复。刷新页面保留任务记录，需重新选择原文件才可继续发送。
- 上传成功后刷新文件列表并显示结果。
- 上传失败时显示错误，保留临时文件供续传或通过 tus 恢复自动重试完成处理；删除上传任务时清理临时数据，创建满 7 天后自动清理。发布采用复制后删除临时文件，不保证原子性：复制期间可能下载到不完整文件，进程被强制终止或清理失败时可能留下残缺文件。
- 单文件大小上限由部署配置决定，整批总大小可超过单文件上限。
- 文件名、大小校验与结果按任务独立处理。复制失败保留完整上传数据；传输完成后由 tus 完成钩子自动发布，不提供独立发布操作；只有发布完成后才显示成功。最后响应丢失或恢复请求失败不得误报成功，也不得丢弃仍然有效的上传地址并重新传输整个文件。

### 2.5 公开浏览与下载

- 应用在 `/public` 提供匿名公开文件页面，通过服务端 loader 按目录读取文件系统；支持面包屑、返回上级、当前目录名称筛选、名称/大小/修改时间排序和手动刷新。
- `/public/download?path=...` 提供流式附件下载，保留原文件名，支持 HEAD 和单段 Range；拒绝非法路径、符号链接和目录下载。
- 点击公开页文件整行触发下载，目录整行进入查看。
- 访客可以看到文件名、大小和修改时间，通过下载按钮保存文件；空目录、无匹配项、加载中和读取失败有对应反馈。
- 文件不存在时返回未找到。
- 公开页面及下载入口需要应用运行。
- 管理端提供公开页入口，以及文件下载链接的生成、展示和复制；链接为同域名的公开下载地址，不创建 Token 或单独保存链接记录。

### 2.6 页面需求

| 页面 | 内容与操作 | 状态 |
| --- | --- | --- |
| 登录页 `/login` | 用户名、密码、登录、公开页入口、主题切换 | 提交中、凭据错误、尝试过多 |
| 文件管理页 | 目录树、文件选择和拖放区域、上传按钮、删除确认、手动刷新 | 加载中、空列表、提交中、成功、失败 |
| 公开文件页 `/public` | 目录浏览、筛选、排序、刷新和单文件下载 | 加载中、正常列表、空目录、无匹配项、未找到、读取失败 |

管理页面只需桌面端基础布局；公开文件页提供桌面和窄屏布局。

### 2.7 运行约束

- 使用单个 HTTPS 域名，`/public` 及其下载和 loader 入口匿名开放；管理页面、管理 loader 和写操作要求认证。
- 管理应用只能操作配置的公开根目录，不能访问服务器其他路径。
- 上传只接受普通文件；目录仅支持浏览和空目录删除。管理端和公开端忽略符号链接及其他特殊文件，拒绝通过它们进行上传或删除。
- 上传内容不能一次性完整载入应用内存。
- 配置、密码哈希、日志和上传临时文件不能放在公开目录中。

### 2.8 验收标准

1. 匿名管理页跳转登录，匿名管理操作及上传返回 401；正确凭据可以登录，错误凭据、篡改或过期会话不能访问管理功能。
2. 管理页展示公开根目录及子目录中的文件和目录，不显示符号链接或其他特殊文件。
3. 管理员选择多个文件并提交后，显示各文件结果，成功的文件出现在列表中，公开端可以获取完整内容。
4. 接收阶段中断时不发布文件，继续后内容完整；暂停保留任务，删除上传清理临时数据且不删除公开文件。复制失败可重试，不保证复制期间或进程被强制终止后没有残缺文件。
5. 上传同名文件时操作失败，原文件保持不变。
6. 管理员确认删除后，文件或空目录从列表消失；取消确认时内容不变；非空目录删除失败。
7. 访客无需认证即可浏览和下载公开文件。
8. 管理页生成的链接与公开页使用同一域名，可匿名下载对应文件。

### 2.9 验证记录与部署约定

- 旧的双域名与 Caddy 直接文件服务部署曾由部署者手动验证（2026-09-13）。此记录来自部署者确认，不作为当前单域名代理配置的验收证据。
- 非 root 运行、宿主机端口仅发布到本机由 Docker 镜像及部署命令的用户、端口绑定与文件权限默认值提供，不作为产品验收约束。
- 示例配置见 [`Caddyfile.example`](../Caddyfile.example)。

## 3. 目标需求（待实现）

### 3.1 统一文件空间与管理

- 所有文件统一存放，上传与代下载只负责不同的获取方式；完成落盘不等于公开分享。本文当前版本中的“上传发布”指上传完成落盘，目标版本的“发布”专指创建公开分享。
- 新上传、代下载取得的文件和新建目录默认私有，只有通过认证的管理员可以浏览和下载。
- 支持创建目录、移动文件和目录、选择上传及代下载的目标目录；同名目标默认拒绝，避免静默覆盖。
- 保持文件系统为文件内容和目录列表的来源；SQLite 保存分享规则及远程下载任务状态，不保存文件内容。
- 移动、重命名或删除分享目标时，必须同步维护分享规则，防止路径被其他文件复用后意外继承公开权限；具体标识与事务方案在实现前设计。

### 3.2 Transfer：跨设备传递

- 管理员在设备 A 经认证上传到指定目录，在设备 B 经认证浏览、下载同一文件，无需先创建公开链接。
- 复用 tus 分块上传、暂停、继续和失败恢复能力；私有下载支持流式响应、HEAD 和 HTTP Range。
- 管理页面适配桌面与手机基本操作，支持选择文件、查看进度、浏览目录和下载。
- 可选临时传输区域属于后续扩展，仍使用统一文件空间；第一阶段不引入自动过期删除、设备同步或 P2P 直连。

### 3.3 Sharing：目录发布

- 管理员选择一个目录并显式发布，获得可复制的公开访问链接；允许多个目录分别发布，分享引用原目录及其当前子项，不复制文件。
- 访客无需管理员凭据，通过有效链接浏览目录、查看文件大小并下载文件；链接只允许访问所发布的目录树。
- 目录中的后续新增、修改和删除反映在分享中。向已分享目录上传或移动文件前，界面应明确提示其会公开。
- 分享列表显示目标目录、访问链接与状态；管理员可以取消发布，取消后新的浏览和下载请求立即失效。已下载的副本无法收回，已开始的传输不承诺强制终止。
- 未分享目录、父目录和兄弟目录不可通过猜测路径、编码路径、符号链接或旧链接访问；失效分享不暴露目标文件信息。
- 分享状态在重启后保留。密码、有效期、下载次数限制与统计不属于首期范围。

### 3.4 Acquisition：HTTP/HTTPS 代下载

- 管理员输入 HTTP/HTTPS URL 并选择私有目标目录，创建后台任务；关闭页面不影响执行。
- 持久化任务来源、目标、状态、已下载字节和错误信息；界面提供排队、下载中、暂停、完成、失败和取消状态，支持暂停、继续、失败重试与取消。
- 并发数和任务大小上限有合理默认值，并允许部署配置；远端未提供总大小时显示已下载字节，不显示虚假百分比。
- 下载流式写入不可访问的临时目录，验证实际长度及可用的资源校验信息后完整落盘到指定目录；未完成文件不能经私有下载或分享暴露，同名目标不能覆盖。
- 重启后恢复任务记录并核对临时文件。续传应校验远端资源标识与 Range 响应；资源变化或不支持续传时明确提示重新下载，不得拼接不同版本内容。
- 取消及失败清理只影响任务临时数据，不删除已完成文件；完成落盘与任务状态更新应可恢复，重试不得重复生成文件或误报成功。
- 只接受 HTTP/HTTPS，拒绝本机、内网、链路本地和其他非公网目标；初始 URL、每次重定向及实际连接地址均须校验，覆盖 IPv4、IPv6 和 DNS 解析变化。
- URL 中的认证信息和敏感查询参数不能写入普通日志；任务创建、状态变化、重试、取消、落盘与安全拒绝应记录可追踪日志。
- 完成后文件保持私有，管理员可再通过 Sharing 发布。首期不支持 BT/Magnet；未来如需支持，交由独立 qBittorrent 服务执行。

### 3.5 认证、存储与部署边界

- 管理页面、私有浏览下载、上传和任务操作全部要求认证；匿名请求仅能通过有效分享入口读取被发布内容。
- 首期保持个人单管理员使用，不要求注册、多租户或角色系统；沿用现有应用登录与会话认证，公开分享权限由 ShareBox 判定。
- Caddy 继续负责 HTTPS 和代理；目标版本不能再通过 `file_server` 绕过应用直接公开整个文件空间。私有入口与分享入口均需经过相应权限检查。
- 逻辑模块化、部署保持单体；仅当下载执行影响 Web 服务，或需要独立重启和资源隔离时再拆 Worker。
- 关键边界与状态变化记录日志；服务端逻辑变更必须运行或编写测试，函数按职责拆分。

## 4. 实施顺序与迁移（待实现）

| 阶段 | 范围 | 完成条件 |
| --- | --- | --- |
| 1 | 私有文件与公开分享边界、旧数据迁移 | 移除公开存储直出路径，认证后可读写，匿名不可读取未分享文件 |
| 2 | 完善文件管理和跨设备传递 | 可创建目录、移动、选择上传目标，手机与桌面可上传及私有下载 |
| 3 | 目录发布 | 可创建、复制和撤销分享链接，权限与状态持久化 |
| 4 | HTTP/HTTPS 代下载 | 任务持久化、限流、恢复、完整落盘及 SSRF 防护通过验收 |
| 5 | 按实际需求扩展 | BT/Magnet 通过外部下载器接入，另行设计与验收 |

迁移必须在切换前备份完整状态目录并停止旧实例，核对文件和权限。旧 `data/` 中的文件保留，但不得静默把整个目录转换成新分享：迁移后默认私有，由管理员明确选择需要重新发布的目录。旧公开链接可能失效，升级说明必须说明影响及重新发布步骤。

迁移必须同步调整 Caddy，移除旧公开目录的 `file_server` 和其他直出入口；仅改应用权限无法保护仍由 Caddy 直接提供的文件。数据库、配置、日志、上传和下载临时文件都不得匿名访问。迁移工具、目录布局、数据库 schema 和回滚流程尚待实现设计；本次文档调整不执行迁移。

## 5. 目标版本验收标准（待执行）

1. 新上传和代下载文件默认私有，匿名请求无法列目录、直接下载或通过旧 Caddy 路径访问；管理员可以在另一台设备认证后下载完整内容。
2. 新建目录、移动和指定目标上传成功；同名冲突保持原文件不变，越界路径与符号链接访问被拒绝。
3. 发布目录后匿名可浏览和下载其子项，不能访问父目录、兄弟目录或临时文件；新加入的子项按目录分享规则可见。
4. 撤销分享后新的列表、HEAD、Range 和下载请求均不可访问，重启后保持撤销；目标移动、删除再重建不会意外公开新文件。
5. 上传或代下载中断、失败、服务重启及完成响应丢失后，未完成内容均不可读；恢复或重试后不覆盖、不重复生成文件、不误报成功。
6. 下载任务关闭页面后继续执行，状态和进度可恢复；暂停、继续、重试、取消及并发限制符合配置。远端忽略 Range 或资源变化时不会错误拼接。
7. HTTP/HTTPS 获取覆盖重定向至内网、IPv6、本机及 DNS 变化的拒绝测试，安全拒绝和任务状态有日志且不泄露敏感 URL。
8. 旧数据迁移保留内容，默认不产生分享；旧直出入口关闭，升级说明能指导管理员重新发布。当前第 2 节的历史验证不能替代这些验收。

## 6. 后续可选扩展

以下功能不属于首期目标，需实际需求驱动另行设计：

- 临时传输区域与可配置过期清理。
- BT/Magnet 外部下载器适配。
- 分享密码、有效期、下载次数限制和统计。
- 同名覆盖策略、批量操作、递归删除和回收站。
- 文件描述、标签、搜索、排序和预览。
- 多管理员与角色权限。
- WebDAV、自动同步、P2P、S3、多服务器、独立 API、CLI 和原生移动客户端。
